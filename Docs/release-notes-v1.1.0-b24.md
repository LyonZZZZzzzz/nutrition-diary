# v1.1.0-b24

- App version: 1.1.0
- Build: 24
- Created: 2026-10-17

## 用户可见变化

- 今日页支持长按菜品，在早餐、午餐、晚餐和加餐之间拖动调整餐次。
- 有饮食记录时四个餐次栏都会显示；空餐次提供明确的拖动落点。
- 拖动经过目标餐次时显示高亮边框和背景，松开后立即更新餐次分组。
- 新增 VoiceOver 辅助操作，可按目标餐次移动菜品。
- 移动后今日总摄入和营养汇总保持不变，不需要删除后重新添加。

## 技术变化

- 新增 `DiaryEntry.moved(to:occurredAt:updatedAt:)`，用同一条记录更新餐次，不改变 ID、session、dayKey、时区、营养快照、来源、照片或创建时间。
- 新增 `AppModel.move(entry:to:)`；目标时间按早餐 08:00、午餐 12:00、晚餐 18:00、加餐 15:00 更新。
- 本地保存后同步原餐次与目标餐次的 HealthKit 汇总，并触发 CloudKit 增量更新。
- 使用自定义 `Transferable` UTI `com.lyonzhu.NutritionDiary.diary-entry`，外部文本和第三方拖放数据不会被接受。
- 同一餐次放下、无效记录、非当前日期数据或正在移动的重复请求均保持无操作。
- 增加餐次标题、空餐次落点和菜品记录的可访问性标识。

## 验证结果

- 新增领域测试验证移动保留营养、照片、会话、双语名称和创建时间。
- 新增 SwiftData 测试验证移动后仍只有一条记录，每日热量汇总保持 71.5 kcal。
- 新增 CloudKit 测试验证同 ID 餐次更新合并后不会生成重复饮食记录。
- 新增 iOS UI 测试验证早餐鸡蛋拖到晚餐后，目标栏出现菜品且今日总摄入不变。
- iOS 27 与 macOS 15+ 构建通过。
- 中英文文案和发布审计通过。

## 已知边界

- 本次不改变同一餐次内部的菜品顺序，也不支持跨日期拖动。
- 照片识别菜品按单条菜品移动，原照片引用继续跟随该记录，不创建照片副本。
- HealthKit 和 CloudKit 最终状态仍需在真机与真实 iCloud 账号下完成发布验收。
