# 1.3.0 (30)

## 用户可见变化

- DeepSeek `deepseek-flash` Vision 成为混合餐照片识别主入口，Apple Intelligence 继续作为可用的本机次入口。
- 多菜、整体或单菜置信度低于 0.80、最佳候选领先不足 0.12、份量跨度异常时，会按需对最多三道低置信度菜品发起第二次近景裁剪识别。
- 照片确认页新增小碗、饭碗、汤碗、20/25 厘米盘、250/350/450 毫升杯和包装每份重量选项，并显示视觉范围与餐具先验融合后的份量建议、置信度和历史参考状态。
- 自动选择门槛提升为最佳候选分数至少 0.80 且领先第二名至少 0.10；达不到时只显示前三候选，不计入记录。
- 用户修改候选后，本机学习会提高已确认映射、降低被拒绝映射，并在同一食物累计三次份量修正后融合历史中位数。
- 过暗、过曝、低对比度、可能模糊或主体过小的照片会提示补拍，而不是强行上传识别。

## 数据与技术变化

- `AnalyzedDish` 向后兼容新增候选别名、0–1 归一化菜品区域、餐具规格和份量置信度可选字段；旧冻结分析数据仍可解码。
- DeepSeek 提示词和结构化 JSON 新增规范菜名、候选别名、配料、烹饪方式、区域、餐具、份量范围与不确定性；仍然禁止返回热量或营养值。
- 新增共享 `PlatewareSpec`、`PhotoRecognitionGate`、`PhotoSecondPassMerger`、`PhotoCandidateSelector`、`PhotoPortionEstimator` 和 `PhotoMatchLearningStore`。
- 本机学习只写入 Application Support 中的 `photo-match-learning.json`：查询先经 SHA-256 规范化哈希，只保存食物 ID、确认/拒绝计数和份量比例；不保存照片、菜名原文或健康数据。
- 本机学习不进入 CloudKit、JSON/媒体备份、版本资源或归档；删除本机数据和重建本地数据库时清除。
- DeepSeek 用户确认弹窗关闭后等待 UI 过渡再呈现结果页，避免结果页被系统 Alert 展示周期吞掉。
- 图片 JSON 解析首次失败时，以更小尺寸和更低 JPEG 质量再尝试一次；网络超时和 5xx 的重试规则保持原实现。

## 验证结果

- 共享包 83 项测试通过，其中新增 8 项照片候选门槛、二次识别、餐具份量、30 份固定称重夹具、本机学习和旧数据解码测试。
- 新增 2 项 iOS UI 固定夹具测试：DeepSeek 上传确认 + 第二次识别，以及低置信度不自动选中。
- iOS 与 macOS 构建、完整 UI 测试、发布审计和归档校验结果以本版本归档 manifest 为准。
- 30 份份量测试为固定合成称重夹具，用于回归算法边界，不等同于真实餐食盲测。

## 已知边界

- 未使用真实 DeepSeek API Key 在 iPhone 17 真机完成混合餐与包装标签验收；本次结论仅覆盖模拟请求、固定夹具和模拟器 UI，不声称已完成真实 API 验收。
- 未完成 30 份真实称重餐食盲测，因此不能对外声称真实场景份量中位绝对误差已达到 30% 以内。
- Vision 质量检查为首版轻量亮度、对比度、边缘和主体估计，不等同于专业摄影质量评分。
- 餐具先验与视觉份量均为估算；用户必须逐菜核对份量。缺失餐具信息时范围会扩大且置信度降低，不会补零。
- 包装标签流程继续使用既有结构，仅共享图片预处理、错误映射和确认组件。
